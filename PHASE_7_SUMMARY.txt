  ✅ TransactionQueue: BlockingQueue<Transaction>
     - Thread-safe by design
     - Blocking operations ensure proper synchronization
  
  ✅ ResponseCache: ConcurrentHashMap

⚙️ LIFECYCLE MANAGEMENT

Startup Sequence:
 1. Spring ApplicationContext initializes
 2. Creates beans: TcpServer, ProcrClient, JsonYamlConverter, AdapterService
 3. AdapterService @PostConstruct called:
    - Verify PROCR health
    - Create AdapterOrchestrator
    - Call orchestrator.start()
 4. orchestrator.start() sequence:
    - Initialize TransactionQueue (capacity=100)
    - Initialize ResponseCache (TTL=30s)
    - Initialize SessionManager (state=IDLE)
    - Start TcpServer (listen on port 5000)
    - Accept connection from Central (blocking)
    - Create SenderThread (start immediately)
    - Create ProcessorThread pool (×2, start immediately)
    - Start ResponseEvictionTask (background daemon)
    - Set running=true
 5. All threads running and waiting for messages

Running State:
 - SenderThread: Blocking read on TCP socket
 - ProcessorThread×2: Blocking dequeue from queue
 - ResponseEvictionTask: Sleeping 5 seconds between evictions
 - Main thread: Returns to Spring ready state

Shutdown Sequence (Graceful):
 1. Spring context shutdown triggered
 2. AdapterService @PreDestroy called:
    - Call orchestrator.shutdown()
 3. orchestrator.shutdown() sequence:
    - Set running=false
    - Call sessionManager.shutdown()
    - Stop SenderThread (gracefully)
    - Stop all ProcessorThreads (gracefully)
    - Wait for all threads (timeout=15s)
    - Stop TcpServer
    - Clear ResponseCache
    - Log completion

🎯 MESSAGE PROCESSING PIPELINE

10-Step Transaction Processing Flow:

Step 1: SenderThread receives JSON transaction from Central
Step 2: Parse JSON, extract transaction_id, amount, client_id
Step 3: Create Transaction object
Step 4: Validate session is ACTIVE with SessionManager
Step 5: Enqueue to TransactionQueue
Step 6: Send ACK to Central {"ack_status": "OK"}

Step 7: ProcessorThread dequeues transaction (blocking)
Step 8: Convert Transaction JSON → YAML
Step 9: POST YAML to PROCR /process endpoint
Step 10: Receive YAML response from PROCR (99% APPROVE, 1% REJECT)

Step 11: Parse YAML response → Response object
Step 12: Cache Response with TTL=30 seconds
Step 13: Convert Response YAML → JSON
Step 14: Send JSON response back to Central via TCP
Step 15: Log metrics (duration, status)
Step 16: Loop back to Step 7 (dequeue next transaction)

Error Handling at Each Step:
- Queue full (Step 5) → Send error ACK to Central
- Session not active (Step 4) → Send error ACK to Central
- PROCR timeout (Step 9) → Send error response to Central
- Conversion error (Step 8, 13) → Send error response to Central
