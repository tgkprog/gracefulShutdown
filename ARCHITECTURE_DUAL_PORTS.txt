╔══════════════════════════════════════════════════════════════════════════════╗
║                         MESSAGE FLOW EXAMPLES                               ║
╚══════════════════════════════════════════════════════════════════════════════╝

1. HEALTH CHECK (Web API)
   ─────────────────────────
   Client: GET http://localhost:8080/central/api/health
      │
      ├─→ Spring DispatcherServlet
      ├─→ MetricsController.getHealth()
      └─→ Returns: {"status":"UP", "tcp_port":5009, "web_port":8080, ...}

2. TRANSACTION FLOW (TCP)
   ─────────────────────────
   Adapter: CONNECT to localhost:5009
      │
      ├─→ TcpServerHandler accepts connection
      ├─→ Adapter sends: {"message_type": "SESSION_START"}
      ├─→ Adapter sends: JSON transaction
      │   {"txn_id": "TXN-123456", "amount": 100, ...}
      ├─→ Server receives transaction
      ├─→ SenderThread processes
      ├─→ ReceiverThread sends back JSON acknowledgment
      │   {"response_type": "APPROVE", "txn_id": "TXN-123456", ...}
      ├─→ Adapter receives acknowledgment
      └─→ Metrics updated & visible via /central/api/status

3. MONITORING (Web API)
   ─────────────────────────
   Dashboard: GET http://localhost:8080/central/api/metrics
      │
      ├─→ MetricsController.getMetrics()
      ├─→ Returns status + history
      └─→ Shows: transactions_sent, transactions_received, etc.
