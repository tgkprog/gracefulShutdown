Critical Open Finding

C1 - Startup order race can disable background tasks

Evidence: AdapterOrchestrator.start() calls startResponseEvictionTask() and startProcrHealthCheckTask() before setting running = true.

  • AdapterOrchestrator.java:108-114
  • Both threads loop on while (running) at AdapterOrchestrator.java:125 and :173.

Impact: Either thread can exit immediately at startup, which may prevent automatic SESSION_START flow and periodic cache eviction.

High Open Findings

H1 - SESSION_END can be rejected for valid zero-transaction session

Evidence: SessionManager.endSession() only allows PROCESSING -> SESSION_ENDED via compareAndSet.

  • SessionManager.java:74-76
  • SenderThread.handleSessionEnd() depends on that result: SenderThread.java:155-164

Requirement impact: REQ-MSG-001 defines TRANSACTION* (zero or more). A session with no transaction should still end cleanly.

H2 - ProcessorThread state-transition warning storm under multi-thread load

Evidence: Each processor thread attempts sessionManager.beginProcessing() once per thread-local flag, but only one thread can succeed.

  • ProcessorThread.java:68-75

Impact: Non-winning threads can repeatedly log warnings, creating noisy logs and false alarm signals.

Medium Open Findings

M1 - Redundant session state sources still present

Evidence: AdapterOrchestrator keeps sessionStarted, while SessionManager tracks lifecycle state.

  • AdapterOrchestrator.java:41,130,139,143

Risk: Drift/inconsistency between orchestrator boolean and state machine.

M2 - Health-check interval mismatch in behavior vs log/comment

Evidence: Comment/log says 10 seconds, loop sleeps 5 seconds.

  • AdapterOrchestrator.java:120,124,151

Impact: Operational confusion and incorrect expectations during incident analysis.

Recommended Remaining Work (Priority Order)

  1. Fix startup ordering: set running = true before starting background threads (or gate loops with a dedicated lifecycle latch).
  2. Allow SESSION_END from both SESSION_STARTED and PROCESSING to preserve TRANSACTION* semantics.
  3. Remove orchestrator sessionStarted and derive from SessionManager.
  4. Adjust ProcessorThread begin-processing logic to avoid repeated warning path on non-first workers.
  5. Align health-check comments/log cadence with actual sleep interval.
